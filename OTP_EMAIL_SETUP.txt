EMAIL OTP SETUP — BEGINNER GUIDE
================================

This project already contains the registration, OTP email, OTP verification,
resend-code and account activation flow. The recipient is taken from the email
entered on the registration form. After a correct OTP, the user is redirected
to the login page.

1. Open the project folder containing manage.py.
2. Copy .env.example and name the copy .env (exactly .env, not .env.txt).
3. Open .env and set EMAIL_HOST_USER to the Gmail address that will SEND OTPs.
4. Create a Google App Password at https://myaccount.google.com/apppasswords.
   Your Google account must have 2-Step Verification enabled.
5. Put that 16-character App Password in EMAIL_HOST_PASSWORD in .env. Remove
   spaces if Google displays the password with spaces. Do not use your normal
   Gmail password. Never share the password or commit .env to GitHub.
6. Save .env. Stop runserver with Ctrl+C and restart it.
7. Run: python manage.py migrate
8. Register with an email inbox you can access, then check Inbox and Spam/Junk.
   Enter the six-digit code on the Verify your email page. Successful verification
   activates the account and redirects to Login.

If EMAIL_HOST_PASSWORD is blank, the project intentionally uses the console email
backend and prints the email to runserver. If configured but sending fails, read
the terminal error, confirm the Gmail/App Password and check Spam/Junk.
The OTP expires after 10 minutes; resend is rate-limited to 30 seconds.

Important: .env is secret and should remain local. .env.example is safe to share
because it contains no App Password.
